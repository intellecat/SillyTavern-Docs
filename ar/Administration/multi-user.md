يسمح الوضع متعدد المستخدمين لعدة أشخاص باستخدام خادم SillyTavern واحد. كل مستخدم لديه إعداداته وإضافاته وبياناته الخاصة. يمكن أيضًا حماية حسابات المستخدمين بكلمة مرور.

!!!warning
توفر كلمات مرور المستخدمين خصوصية أساسية بين مستخدمي الإعداد متعدد المستخدمين. إنها ليست ميزة أمان ولا ينبغي اعتبارها كذلك. يتم تخزين جميع بيانات المستخدم (بما في ذلك سجل الدردشة ومفاتيح API والمعلومات الحساسة الأخرى) بنص عادي على الخادم. يمكن عرضها وتعديلها من قبل أي شخص لديه حق الوصول إلى نظام ملفات الخادم. **لا تستخدم SillyTavern على خادم عام أو مع مستخدمين غير موثوق بهم.**
!!!

## التكوين

لتمكين واستخدام الوضع متعدد المستخدمين، قم بتحرير ملف `config.yaml`:

```yaml
# تمكين الوضع متعدد المستخدمين
enableUserAccounts: true
# تمكين وضع تسجيل الدخول السري: يخفي قائمة المستخدمين في شاشة تسجيل الدخول
enableDiscreetLogin: true
```

1. عندما يتم تعطيل إعداد حساب المستخدم، يتم استخدام حساب مسؤول احتياطي `default-user` لتخزين بيانات المستخدم.
2. عندما يتم تعطيل إعداد تسجيل الدخول السري، يتم عرض قائمة المستخدمين النشطين في شاشة تسجيل الدخول. إذا تم تمكينه، يجب على المستخدم إدخال معرفه يدويًا.

!!!info
لا يمكنك _حذف_ حساب `default-user` من قائمة المستخدمين لأنه يستخدم لخدمة بيانات المستخدم في حالة تعيين `enableUserAccounts` على `false`. لكن يمكنك _تعطيله_ لإخفائه من القائمة ومنع تسجيلات الدخول.
!!!

## معرفات المستخدمين

المعرف هو المعرف الفريد للمستخدم. يمكن أن يتكون فقط من أحرف صغيرة وأرقام وشرطات.

يفترض المسار إلى دليل بيانات المستخدم استخدام النمط التالي: `%DATA_ROOT%/%USER_HANDLE%`.

أمثلة على معرفات المستخدمين الصالحة:

- default-user
- juan555
- flux-the-cat
- cool-guy1337

## الأدوار

- **مسؤول** - يمكنه إدارة (إنشاء، حذف، تعديل) المستخدمين الآخرين. يمكنه تثبيت الإضافات لجميع المستخدمين.
- **مستخدم** - لا يمكنه إدارة المستخدمين الآخرين. يمكنه تثبيت الإضافات لأنفسهم فقط.

باستثناء الوصول إلى لوحة المسؤول، فإن كلا دوري المستخدم متطابقان وظيفيًا ويمكنهما استخدام مجموعة كاملة من ميزات SillyTavern دون أي قيود. تنفيذ أذونات المستخدم قيد التطوير.

يتم إنشاء جميع حسابات المستخدمين كمستخدمين عاديين أولاً، ثم يمكن ترقيتهم إلى مسؤولين إذا لزم الأمر.

### شاشة تسجيل الدخول

هناك يمكنك تحديد حساب مستخدم لاستخدامه. لديه نمطان، اعتمادًا على قيمة تكوين `enableDiscreetLogin`.

يتم تجاوز شاشة تسجيل الدخول ولا يتم عرضها عندما يكون لديك مستخدم نشط واحد فقط وهو غير محمي بكلمة مرور.

### ملف تعريف المستخدم

يمكنك الوصول إلى قائمة الإدارة الذاتية للحساب باستخدام زر "الحساب" تحت لوحة "إعدادات المستخدم" في شريط القائمة العلوي.

1. اسم العرض - يستخدم في شاشة تسجيل الدخول، ويمكن تغييره. لا يرتبط بالشخصيات وغير مرئي لواجهات برمجة تطبيقات AI - لا يزال بإمكانك استخدام أكبر عدد ممكن من الشخصيات كما تريد.
2. صورة الملف الشخصي - تستخدم في شاشة تسجيل الدخول. يمكنك إما استخدام صورة مخصصة، أو صورة الشخصية الافتراضية (إذا تم تعيينها)، أو الشخصية المستخدمة الأخيرة بخلاف ذلك.
3. كلمة المرور - تعكس أيقونة القفل حالة حماية الحساب (قفل مفتوح = لا توجد كلمة مرور). يمكن تعيين كلمة المرور أو تغييرها أو إزالتها باستخدام زر "تغيير كلمة المرور".
4. لقطات الإعدادات - الوصول إلى ومراجعة النسخ الاحتياطية لملف `settings.json` الخاص بك، مع القدرة على إنشاء أو استعادة اللقطات.
5. تنزيل النسخ الاحتياطي - تنزيل أرشيف لمجلد بيانات المستخدم الخاص بك.
6. إعادة تعيين الإعدادات - إعادة تعيين الإعدادات الافتراضية للمصنع، مع ترك البيانات الأخرى (الشخصية، الدردشات) سليمة.

## استرداد كلمة المرور

1. يمكن استرداد كلمة المرور من شاشة تسجيل الدخول. تحتاج إلى الوصول إلى وحدة تحكم الخادم للحصول على رمز استرداد لمرة واحدة (يتكون من 4 أرقام).
2. بدلاً من ذلك، يمكنك استخدام برنامج نصي مساعد في خادم SillyTavern لإعادة تعيين كلمة المرور عن طريق توفير معرف المستخدم.

```txt
الاستخدام: node recover.js [account] (password)
مثال: node recover.js admin SecurePassword
```

## هيكلة المحتوى

لإضافة محتوى مخصص للمستخدمين، يمكنك استخدام ميزة هيكلة المحتوى. تتيح لك هذه الميزة تحديد مجموعة من الملفات التي سيتم نسخها إلى دليل بيانات كل مستخدم عند بدء تشغيل الخادم.

يجب عليك إنشاء ملف `index.json` في دليل `/default/scaffold` لكي تعمل هذه الميزة. الصيغة هي نفسها للمحتوى الافتراضي. يجب أن تكون جميع مسارات الملفات نسبية إلى دليل `/default/scaffold`، ويمكنك تنظيم الملفات باستخدام أدلة فرعية.

يتم نسخ الملفات المهيكلة قبل الملفات الافتراضية، مما يعني أنها ستتجاوز أي ملفات افتراضية (الإعدادات المسبقة/الإعدادات/إلخ.) التي لها نفس اسم الملف.

!!!tip
يحتوي كل دليل بيانات مستخدم على ملف `content.log` يسرد جميع الملفات المنسوخة من أدلة الهيكل والافتراضي. قم بإزالة هذا الملف لإجبار الخادم على مزامنة المحتوى مرة أخرى عند إعادة التشغيل التالية.
!!!

### أنواع المحتوى المعترف بها

| النوع | القيمة |
|-------------------------------|----------------------|
| settings.json | `'settings'` |
| بطاقة الشخصية | `'character'` |
| صور الشخصية المتحركة | `'sprites'` |
| صورة الخلفية | `'background'` |
| ملف World Info | `'world'` |
| صورة رمزية للشخصية | `'avatar'` |
| سمة واجهة المستخدم | `'theme'` |
| سير عمل ComfyUI | `'workflow'` |
| إعداد مسبق لـ KoboldAI Classic | `'kobold_preset'` |
| إعداد مسبق لإكمال الدردشة | `'openai_preset'` |
| إعداد مسبق لـ NovelAI | `'novel_preset'` |
| إعداد مسبق لإكمال النص | `'textgen_preset'` |
| قالب وضع التعليمات | `'instruct'` |
| قالب تنسيق السياق | `'context'` |
| إعداد مسبق لـ MovingUI | `'moving_ui'` |
| مجموعة الردود السريعة | `'quick_replies'` |
| قالب موجه النظام | `'sysprompt'` |
| قالب تنسيق التفكير | `'reasoning'` |

### مثال (`/default/scaffold/index.json`)

```json
[
    {
        "filename": "themes/Midnight.json",
        "type": "theme"
    },
    {
        "filename": "backgrounds/city.png",
        "type": "background"
    },
    {
        "filename": "characters/Charlie.png",
        "type": "character"
    }
]
```
