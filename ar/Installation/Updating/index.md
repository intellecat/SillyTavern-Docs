# كيفية تحديث SillyTavern

ابحث عن نظام التشغيل الخاص بك أدناه واتبع التعليمات لتحديث ST.

!!! لتعليمات التثبيت، راجع صفحة [التثبيت](/Installation/index.md).

يفترض هذا الدليل أنك قمت بالفعل بتثبيت وتشغيل SillyTavern مرة واحدة على الأقل.
!!!

----

## Linux/Termux أو MacOS

بالتأكيد قمت بالتثبيت عبر git، لذا فقط قم بـ 'git pull' داخل دليل SillyTavern.

- `cd SillyTavern` للدخول إلى المجلد الصحيح.
- `git pull` للحصول على التحديث.
- `./start.sh` أو `bash start.sh` لبدء ST.

----

## Windows

>جرب أولاً استخدام `UpdateAndStart.bat` الموجود في مجلد تثبيت SillyTavern الأساسي.

إذا فشل ذلك، عد إلى هنا وتابع القراءة.

### الطريقة 1 - GIT

نوصي دائماً المستخدمين بالتثبيت باستخدام 'git'. إليك السبب:

عندما تقوم بالتثبيت عبر `git clone`، كل ما عليك فعله للتحديث هو كتابة `git pull` [في سطر الأوامر في مجلد ST](https://www.google.com/search?q=how+to+open+command+prompt+in+a+folder).
بدلاً من ذلك، إذا أعطاك موجه الأوامر مشاكل (وقمت بتثبيت GitHub Desktop)، يمكنك استخدام قائمة `Repository` واختيار `Pull`.

يتم تطبيق التحديثات تلقائياً وبشكل آمن.

#### "مساعدة، قمت بالتثبيت في الأصل عبر Zip والآن أريد التحويل إلى تثبيت Git"

لقد اخترت طريقاً حكيماً.

نظراً لأن تثبيتك تم عبر Zip، ستحتاج إلى إجراء تثبيت جديد باستخدام git.

لحسن الحظ لدينا [تعليمات](/Installation/Windows.md) حول كيفية القيام بذلك.

بمجرد استخدام git لتثبيت SillyTavern جديد في مجلد مختلف، عد إلى هذه الصفحة وتابع إلى **الخطوة 4** من تعليمات 'تحديث Zip' أدناه.

### الطريقة 2 - ZIP

إذا أصررت على التثبيت عبر zip، فإليك العملية المملة للقيام بالتحديث:

1. قم بتنزيل zip الإصدار الجديد.
2. قم بفك ضغطه في مجلد خارج تثبيت ST الحالي.
3. قم بإجراء المعتاد لإعداد نظام التشغيل الخاص بك لتثبيت متطلبات NodeJS.

4. انسخ الملفات/المجلدات التالية حسب الضرورة(*) من تثبيت ST القديم الخاص بك:

    (*) 'حسب الضرورة' = "إذا قمت بعمل أي محتوى مخصص يتعلق بتلك المجلدات".

    #### التحديث >=1.12.0

    انسخ دليل `/data` وملف `config.yaml` من تثبيت إلى آخر. إذا كان لديك امتدادات على مستوى الخادم (مثبتة لـ "جميع المستخدمين") تريد الحفاظ عليها، انسخ أيضاً دليل `/public/scripts/extensions/third-party`.

    #### التحديث من <1.12.0 إلى >1.12.0

    يتضمن 1.12.0 إجراء ترحيل تلقائي. الخطوات أدناه مطلوبة *فقط* إذا تم مقاطعة الترحيل أو حدث خطأ.

5. قم بتشغيل تثبيت الخادم المحدث مرة واحدة على الأقل لإنشاء دليل `/data/default-user`.
6. انقل الملفات من `/public` القديم إلى `/data/default-user` الجديد حسب الضرورة.

    لا يوجد أي من المجلدات إلزامياً، لذا انسخ فقط ما تحتاجه.

    **ملاحظة: لا تنسخ مجلد /PUBLIC/ بأكمله**

    قد يؤدي القيام بذلك إلى كسر التثبيت الجديد ومنع ظهور الميزات الجديدة.

    ```plaintext
    Assets
    Backgrounds
    Characters
    Chats
    Context
    Groups
    Group chats
    Instruct
    movingUI
    KoboldAI Settings
    NovelAI Settings
    OpenAI Settings
    QuickReplies
    TextGen Settings (textgen = ooba)
    Themes
    User Avatars
    Worlds
    User
    settings.json
    secrets.json <---- هذا موجود في المجلد الأساسي، وليس /public/
    ```

7. بمجرد نسخ تلك المجلدات/الملفات، الصقها في مجلد /data/default-user (مع وضع secrets.json في جذر المجلد) من التثبيت الجديد.
8. ابدأ SillyTavern مرة أخرى بالطريقة المناسبة لنظام التشغيل الخاص بك، وصلِّ أنك فعلت ذلك بشكل صحيح.
9. إذا ظهر كل شيء، يمكنك حذف مجلد ST القديم بأمان.

### مشاكل التحديث الشائعة

#### "هناك تعارضات لم يتم حلها في دليل العمل."

هذا يعني أنك قمت بتعديل الملفات الافتراضية التي تم تغييرها في المستودع البعيد (مثل إعدادات مسبقة).

لإصلاح هذا، قم بتشغيل هذا في terminal. استخدمه بحذر، لأنه يمكن أن يكون مدمراً. تأكد من وجود نسخة احتياطية إذا لزم الأمر.

```bash
git merge --abort
git reset --hard
git pull --rebase --autostash
```

#### تغييرات الملفات تمنع git pull

- إذا قمت بتغيير ملفات نظام SillyTavern، فقد لا يعمل `git pull`.
- في بعض الأحيان قد يتطلب التحديث منا تغيير ملف مهم، مما قد يسبب نفس المشكلة.
- عادة ما تكون ملفات الإعدادات المسبقة الافتراضية أو `package-lock.json`.
- في هذه الحالة، يمكنك محاولة نقل الملف إلى مجلد مختلف (أو حذف الملف) ثم إجراء `git pull`.
- حل آخر هو استخدام `git pull --rebase --autostash`

#### خطأ: لا يمكن العثور على الوحدة "***" عند بدء الخادم

- هذا يعني أن SillyTavern أضاف متطلب حزمة npm جديداً.
- قم بتشغيل `npm install` في دليل SillyTavern لإصلاح هذا. ستفعل سكريبتات Start.bat و start.sh المقدمة ذلك تلقائياً.
- لم يساعد؟ احذف مجلد node_modules

**Windows**

```bash
rmdir /s /q node_modules
npm cache clean --force
npm install
```

**Unix/Linux**

```bash
rm -rf node_modules
npm cache clean --force
npm install
```

## Docker

1. افتح نافذة terminal وانتقل إلى دليل docker الخاص بك `cd SillyTavern/docker`
2. احذف حاويتك باستخدام `docker compose down`
3. احذف صورة SillyTavern docker من ذاكرة التخزين المؤقت `docker rmi ghcr.io/sillytavern/sillytavern:latest` (استبدل `sillytavern:latest` بـ `sillytavern:staging` إذا كنت تستهدف فرع staging.)
4. أعد بناء الحاوية باستخدام `sudo docker compose up -d`

إذا سارت الأمور بسلاسة، يجب أن يبدأ docker في إعادة تنزيل الصورة، وستكون جاهزاً للعمل قريباً. إذا واجهت أي مشاكل، راجع القسم التالي من هذا الدليل.

### مشاكل التحديث الشائعة
#### أستخدم Docker واختفت جميع بياناتي بعد التحديث!

يجب عليك اتباع [دليل الترحيل لحاويات Docker](/Installation/Updating/ST-1.12.0-Migration-Guide.md#containerized-docker-installs)
 لتحديث تعيينات الوحدة التخزينية لنموذج البيانات الجديد المقدم في 1.12.0

#### رفض الإذن عند تشغيل أوامر docker

هذه مشكلة Linux، وتشير إلى أن أذوناتك غير معدة بشكل صحيح. هناك طريقتان للتغلب على هذا:

1. **الطريقة السهلة**: إذا كان لديك وصول sudo على المستخدم الخاص بك، فقط قم بإضافة `sudo` قبل الأوامر (على سبيل المثال: `sudo docker compose down`)
2. **الطريقة الصحيحة**: أصلح أذوناتك. يختلف هذا اعتماداً على إصدار Linux الذي تستخدمه. هناك الكثير من الأدلة على الإنترنت لمساعدتك في إصلاح هذه المشكلة.
