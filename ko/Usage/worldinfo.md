# World Info

**World Info(Lorebooks 또는 Memory Books라고도 함)는 ST에서 프롬프트를 동적으로 삽입하여 AI 응답을 안내하는 강력한 도구입니다.**

일반적으로 World Info(줄여서 WI)는 가상 세계의 세부 정보에 대한 AI의 이해를 향상시키는 데 사용되지만 World Info 항목을 사용하여 프롬프트에 삽입하려는 모든 것을 삽입할 수 있습니다.

항목과 연결된 키워드가 메시지 텍스트에 있을 때만 World Info 항목에서 관련 정보를 삽입하는 동적 사전처럼 작동합니다.

SillyTavern 엔진은 적절한 lore를 활성화하고 원활하게 프롬프트에 통합하여 AI에 배경 정보를 제공합니다.

*World Info는 AI를 원하는 콘텐츠로 안내하는 데 도움이 되지만 생성된 출력 메시지에 나타나는 것을 보장하지는 않습니다. 이는 모델이 추가 정보를 얼마나 잘 활용하는지에 따라 다릅니다!*

## 프로 팁

* World Info 엔진은 매우 강력한 프롬프트 관리 도구입니다. 캐릭터 lore만 추가하는 데 집착하지 말고 자유롭게 실험해 보세요.
* 활성화 키워드, 제목 및 **Content** 필드에 없는 기타 정보는 컨텍스트에 삽입되지 않으므로 각 World Info 항목에는 포괄적이고 독립적인 설명이 있어야 합니다.
* 풍부하고 상세한 world lore를 만들려면 재귀 활성화를 사용하여 항목을 상호 연결하고 서로 참조할 수 있습니다. 아래 [재귀](#recursive-scanning)에 대한 자세한 내용을 참조하세요.
* SillyTavern은 삽입된 배경 정보에 대한 유연한 컨텍스트 예산을 제공합니다. 프롬프트 토큰을 절약하려면 항목 내용을 간결하게 유지하는 것이 좋습니다.

## 컨텍스트별 소스

전역 World Info 선택기 외에도 lorebook을 캐릭터, 페르소나 또는 개별 채팅과 같은 특정 컨텍스트에 할당할 수 있습니다. 이러한 컨텍스트별 소스는 해당 캐릭터, 페르소나 또는 채팅이 활성화되어 있을 때 자동으로 활성화됩니다.

### 캐릭터 Lore

선택적으로 World Info 파일을 캐릭터에 할당하여 해당 캐릭터와의 모든 채팅(그룹 포함)에서 전용 lore 소스로 사용할 수 있습니다.

하나의 기본 World Info를 캐릭터에 바인딩할 수 있습니다. 이렇게 하려면 캐릭터 관리 패널로 이동하여 지구본 버튼을 클릭한 다음 드롭다운 목록에서 World Info를 선택하고 "확인"을 클릭합니다. 캐릭터를 내보낼 때 이 파일도 캐릭터 카드 데이터에 포함됩니다.

바인딩 해제, 변경 또는 추가 World Info 파일을 캐릭터 lore로 할당하려면 지구본 버튼을 Shift+클릭하거나 "More..."를 클릭한 다음 "World Info 연결"을 클릭합니다. 기본 World Info 파일만 캐릭터와 함께 내보내집니다.

World Info 파일의 이름을 변경하면 해당 lorebook을 참조하는 모든 캐릭터에서 선택적으로 다시 연결할지 묻는 메시지가 표시됩니다. 이를 통해 이름 변경 후에도 기존 캐릭터 lore 바인딩이 그대로 유지됩니다.

### 페르소나 Lorebook

World Info 파일을 현재 활성화된 [페르소나](/Usage/personas.md)에 할당할 수 있습니다. 이 lorebook의 항목은 어떤 캐릭터나 채팅이 열려 있는지에 관계없이 해당 페르소나가 선택될 때마다 활성화됩니다.

페르소나에 lorebook을 할당하려면 **페르소나 관리** 패널을 열고 <i class="fa-solid fa-globe"></i> **페르소나 Lore** 버튼을 클릭하세요. 드롭다운 목록에서 World Info 파일을 선택합니다. lorebook이 이미 바인딩되어 있으면 버튼을 클릭할 때 lorebook 편집기가 바로 열립니다.

!!!
lorebook이 이미 바인딩되어 있을 때 할당 팝업을 다시 열려면 페르소나 Lore 버튼에서 **길게 누르기**(모바일) 또는 **Shift+클릭 / Alt+클릭**(데스크톱)을 사용하세요.
!!!

### 채팅 Lorebook

World Info 파일을 개별 채팅에도 할당할 수 있습니다. 채팅에 바인딩된 lorebook의 항목은 해당 특정 대화에서만 활성화되며 동일한 캐릭터와의 다른 채팅으로는 이어지지 않습니다.

채팅에 lorebook을 할당하려면 캐릭터 관리 패널에서 <i class="fa-solid fa-passport"></i> **채팅 Lore** 버튼을 클릭하세요. 드롭다운 목록에서 World Info 파일을 선택합니다. lorebook이 이미 바인딩되어 있으면 버튼을 클릭할 때 lorebook 편집기가 바로 열립니다.

!!!
lorebook이 이미 바인딩되어 있을 때 할당 팝업을 다시 열려면 채팅 Lore 버튼에서 **길게 누르기**(모바일) 또는 **Shift+클릭 / Alt+클릭**(데스크톱)을 사용하세요.
!!!

### Lore 삽입 전략

AI 응답을 생성할 때 캐릭터 World Info 및 기타 보조 소스의 항목은 전역 World Info 선택기의 항목과 결합됩니다. 기본적으로 항목은 다음 순서로 삽입됩니다:

* [채팅 Lore](#chat-lorebook)
* [페르소나 Lore](#persona-lorebook)
* 다음 전략 중 하나를 사용하는 캐릭터 Lore 또는 전역 Lore:

#### Sorted Evenly (기본값)

소스를 무시하고 모든 항목이 하나의 큰 파일의 일부였던 것처럼 삽입 순서에 따라 정렬됩니다.

#### Character Lore First

캐릭터 World Info의 항목이 삽입 순서대로 먼저 포함된 다음 전역 World Info의 항목이 포함됩니다.

#### Global Lore First

전역 World Info의 항목이 삽입 순서대로 먼저 포함된 다음 캐릭터 World Info의 항목이 포함됩니다.

## World Info 항목

### Key

World Info 항목의 활성화를 트리거하는 키워드 목록입니다. 키는 기본적으로 대소문자를 구분하지 않습니다(이것은 [구성 가능](#case-sensitive-keys)합니다).

#### 키로서의 정규 표현식(Regex)

키는 regex를 지원하여 일치에 대한 보다 유연한 접근 방식을 허용합니다. 이를 통해 선택적 단어나 문자, 간격 및 regex가 제공하는 모든 기타 유틸리티를 사용하여 보다 동적인 콘텐츠를 일치시킬 수 있습니다.
정의된 키가 유효한 regex인 경우(Javascript regex 스타일, `/`를 구분 기호로 사용. 모든 플래그가 허용됨) 항목을 트리거해야 하는지 확인할 때 그렇게 처리됩니다. 여러 regex를 별도의 키로 입력할 수 있으며 서로 나란히 작동합니다. regex 내부에서는 쉼표가 가능합니다. 일반 텍스트 키는 키 구분 기호로 처리되므로 쉼표를 지원하지 않습니다.

고급 regex 일치의 사용 사례 예:
캐릭터가 날씨 관련 작업을 수행할 때 삽입해야 하는 항목/지침

```js
/(?:{{char}}|he|she) (?:is talking about|is noticing|is checking whether|observes) (?:the )?(rainy weather|heavy wind|it is going to rain|cloudy sky)/i
```

Regex 구문 및 가능성에 대한 자세한 정보: [Regular expressions - JavaScript | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions)

##### 고급 Regex 메시지별 일치

ST는 WI 스캔 버퍼의 모든 채팅 메시지 앞에 `character name:`을 접두사로 붙이고 v1.12.6 이후에는 문자 값 1(`\x01`)을 사용하여 연결합니다.
즉, 해당 구분 문자와 연결된 regex를 사용하여 특정 캐릭터의 특정 입력 또는 출력을 일치시킬 수 있습니다.

예를 들어 사용자가 "hello"라고 말하는 것만 일치시키려면 다음 regex를 사용할 수 있습니다:

```js
/\x01{{user}}:[^\x01]*?hello/
```

#### 키 입력

키워드를 입력하는 두 가지 모드가 있으며 각각 약간 다른 UI가 있습니다. ⌨️ *일반 텍스트 모드*(기본값)에서 키는 단일 텍스트 필드에 쉼표로 구분된 목록으로 입력할 수 있습니다. Regex도 포함할 수 있지만 특별한 강조 표시는 없습니다. ✨ *fancy 모드*에서는 키가 별도의 요소로 나타나며 regex는 그렇게 강조 표시됩니다. 컨트롤은 키 편집 및 삭제를 지원합니다. 모드는 입력 컨트롤 내부의 인라인 버튼을 통해 전환할 수 있습니다.

### Optional Filter

기본 키와 함께 추가 키워드의 쉼표로 구분된 목록입니다.
인수가 제공되지 않으면 이 플래그는 무시됩니다.
AND ANY, NOT ANY 또는 NOT ALL에 대한 논리를 지원합니다

1. AND ANY = 기본 키와 선택적 필터 키 중 하나가 스캔된 컨텍스트에 있는 경우에만 항목을 활성화합니다.
2. AND ALL = 기본 키와 모든 선택적 필터 키가 있는 경우에만 항목을 활성화합니다.
3. NOT ANY = 기본 키와 선택적 필터 키가 없는 경우에만 항목을 활성화합니다.
4. NOT ALL = 모든 선택적 필터가 스캔된 컨텍스트에 있으면 기본 키 트리거에도 불구하고 항목 활성화를 방지합니다.

이러한 키는 [regex](#regular-expression-regex-as-keys)도 지원합니다.

### 항목 내용

항목 활성화 시 프롬프트에 삽입되는 텍스트입니다.

### 삽입 순서

숫자 값. 여러 항목이 한 번에 활성화된 경우 항목의 우선순위를 정의합니다. 순서 번호가 큰 항목은 컨텍스트 끝에 가까이 삽입되어 출력에 더 많은 영향을 미칩니다. 예를 들어 순서 번호가 100인 항목은 순서 번호가 250인 항목보다 먼저 컨텍스트에 나타납니다.

### 삽입 위치

* **Before Char Defs:** World Info 항목은 캐릭터의 설명 및 시나리오 앞에 삽입됩니다. 대화에 보통 수준의 영향을 미칩니다.
* **After Char Defs:** World Info 항목은 캐릭터의 설명 및 시나리오 뒤에 삽입됩니다. 대화에 더 큰 영향을 미칩니다.
* **Before Example Messages:** World Info 항목은 예제 대화 블록으로 구문 분석되어 캐릭터 카드에서 제공하는 예제 앞에 삽입됩니다.
* **After Example Messages:** World Info 항목은 예제 대화 블록으로 구문 분석되어 캐릭터 카드에서 제공하는 예제 뒤에 삽입됩니다.
* **Top of AN:** World Info 항목은 작성자 노트 내용의 맨 위에 삽입됩니다. 작성자 노트 위치에 따라 가변적인 영향을 미칩니다.
* **Bottom of AN:** World Info 항목은 작성자 노트 내용의 맨 아래에 삽입됩니다. 작성자 노트 위치에 따라 가변적인 영향을 미칩니다.
* **@ D:** World Info 항목은 채팅의 특정 깊이에 삽입됩니다(깊이 0이 프롬프트의 맨 아래).
  * ⚙️ - 시스템 역할 메시지로
  * 👤 - 사용자 역할 메시지로
  * 🤖 - 어시스턴트 역할 메시지로
* **Outlet:** World Info 항목은 자동으로 삽입되지 않습니다. 대신 해당 내용이 명명된 outlet에 저장되므로 [`{{outlet::Name}}` 매크로](#outlet-name)로 호출하여 프롬프트에 표시되는 위치를 정확하게 결정할 수 있습니다.

예제 메시지 항목은 프롬프트 작성 설정(Instruct Mode 또는 Chat Completion 프롬프트 관리자)에 따라 형식이 지정됩니다. 또한 예제 메시지 동작 규칙을 따릅니다: 전체 컨텍스트에서 점진적으로 푸시되거나, 항상 유지되거나, 완전히 비활성화됩니다.

작성자 노트가 비활성화된 경우(삽입 빈도 = 0) A/N 위치의 World Info 항목은 무시됩니다!

### Outlet Name

**Outlet** 삽입 위치가 선택되면 항목에 대한 추가 **Outlet Name** 필드를 사용할 수 있습니다. 여기에 제공하는 이름은 항목을 함께 그룹화하고 프롬프트에 수동으로 가져오는 데 사용할 토큰을 정의합니다.

[Prompt Manager](./Prompts/prompt-manager.md) 또는 [Advanced Formatting](./Prompts/advancedformatting.md) 프롬프트 필드에서 `{{outlet::YourName}}` 매크로를 사용합니다. 프롬프트가 작성되면 매크로는 동일한 outlet 이름을 공유하는 모든 World Info 항목의 결합된 내용으로 대체되며, 줄 바꿈으로 구분되고 [삽입 순서](#insertion-order) 값으로 정렬됩니다.

outlet 항목에 이름이 없으면 생성 중에 건너뛰므로 필드를 반드시 입력하세요. Outlet 이름은 일관된 레이블을 재사용하기 쉽도록 이미 사용한 이름을 기반으로 자동 완성을 지원합니다.

#### 제한 사항 및 주의 사항

* World Info 항목 내에 outlet 매크로를 배치하는 것은 지원되지 않으며 작동하지 않습니다. 이는 World Info의 평가 순서와 충돌하며 무한 루프로 이어질 수 있습니다.
* outlet 중첩은 지원되지 않습니다. outlet 매크로를 다른 outlet의 내용 안에 배치할 수 없습니다. 위와 동일하게 무한 루프로 이어질 수 있습니다.
* 캐릭터 카드 필드(설명, 성격, 시나리오 등)는 outlet을 확장할 수 없습니다. 이러한 필드는 World Info 트리거에 대한 [추가 일치 소스](#additional-matching-sources)로 작동할 수 있도록 일찍 구문 분석되므로 텍스트가 처리될 때 outlet을 사용할 수 없습니다. outlet 내용을 프롬프트 본문에 배치해야 하는 경우 다른 매크로 인식 필드를 사용하세요.
* 작성자 노트 편집기도 outlet을 확인할 수 없습니다. 작성자 노트 주위에 outlet 내용을 배치하려면 매크로를 사용하는 대신 항목을 **Top of AN** 또는 **Bottom of AN** 삽입 위치에 할당하세요.
* Outlet 이름은 대소문자를 구분합니다. `{{outlet::}}` 매크로는 항목의 **Outlet Name**과 정확히 동일한 대문자를 사용해야 합니다. 그렇지 않으면 내용이 반환되지 않습니다.
* outlet 이름의 선행 또는 후행 공백은 매크로를 호출할 때 무시되므로 추가 공백으로 저장된 이름은 일치하지 않습니다. 이름이 올바르게 확인될 수 있도록 패딩을 피하세요.
* 할당된 내용이 없는 outlet 매크로는 빈 문자열로 대체됩니다.

### 항목 제목 / 메모

항목에 레이블을 지정하기 위한 편의를 위한 텍스트 필드로, AI 또는 트리거 논리에서 사용되지 않습니다.

비어 있으면 "빈 메모 채우기" 버튼을 클릭하여 항목의 첫 번째 키를 사용하여 역으로 채울 수 있습니다.

### 전략

1. 🔵 (파란색 원) = 항목에는 키워드가 필요하지 않으며 콘텐츠와 관계없이 트리거됩니다.
2. 🟢 (녹색 원) = 항목은 키워드가 있는 경우에만 트리거됩니다.
3. 🔗 (체인 링크) = 항목은 임베딩 유사성에 의해 삽입될 수 있습니다.

각 항목에는 항목을 활성화 또는 비활성화할 수 있는 토글도 있습니다.

### 확률 (트리거 %)

이 값은 항목이 어떤 수단(상수, 기본 키, 재귀)으로 활성화될 때 삽입되지 않을 가능성을 추가하는 추가 필터처럼 작동합니다.

1. 확률 = 100은 항목이 모든 활성화에서 삽입됨을 의미합니다.
2. 확률 = 50은 항목이 1:1 확률로 삽입됨을 의미합니다.
3. 확률 = 0은 항목이 삽입되지 않음을 의미합니다(본질적으로 비활성화).

채팅에서 무작위 이벤트를 만드는 데 사용하세요. 예를 들어 메시지에 이름이 언급된 경우 모든 메시지에 Elder God를 깨울 확률이 1%일 수 있습니다.

### 포함 그룹

포함 그룹은 동일한 그룹 레이블을 가진 여러 항목이 동시에 트리거될 때 항목이 선택되는 방식을 제어합니다. 동일한 그룹 레이블을 가진 여러 항목이 활성화된 경우 하나만 프롬프트에 삽입됩니다.

기본적으로 선택한 항목은 그룹 가중치(기본값은 100포인트)를 기반으로 무작위로 선택됩니다. 숫자가 높을수록 선택 확률이 높습니다. 이를 통해 트리거된 항목 중에서 무작위로 선택할 수 있어 상호 작용에 놀라움과 다양성의 요소를 추가합니다.

단일 항목은 쉼표로 구분된 목록으로 정의된 경우 여러 포함 그룹의 일부가 될 수 있습니다. 위에서 설명한 것과 동일한 논리가 적용됩니다. 해당 항목이 트리거되면 그룹의 일부인 다른 모든 항목이 *비활성화*됩니다. 따라서 그룹 중 하나가 활성화되면 이 항목은 활성화되지 않습니다.

### 포함 우선순위

[포함 그룹](/Usage/worldinfo.md#inclusion-group)을 통해 활성화되는 항목을 더 잘 제어하려면 '포함 우선순위' 설정을 사용할 수 있습니다. 이 옵션을 사용하면 그룹 가중치 확률을 무작위로 롤링하는 대신 결정론적으로 선택할 항목을 지정할 수 있습니다.

동일한 그룹 레이블과 이 설정이 켜진 여러 항목이 활성화된 경우 가장 높은 '순서' 값을 가진 항목이 선택됩니다. 이는 포함 그룹을 통해 대체 시퀀스를 만드는 데 유용합니다. 예를 들어 더 많은 강조가 있는 낮은 깊이 항목의 우선순위를 지정하거나 둘 다 유효한 경우 다른 항목보다 장면 설정에 대한 특정 지침을 선택합니다.

### 그룹 점수 사용

이 설정이 전역적으로 또는 항목별로 활성화되면 활성화된 항목 키의 수가 그룹 승자 선택을 결정합니다. 가장 높은 키 일치 수를 가진 그룹의 하위 집합만 그룹 가중치 또는 포함 우선순위에 의해 활성화되도록 남습니다. 나머지는 비활성화되고 그룹에서 제거됩니다.

큰 그룹의 개별 항목에 대해 더 많은 특정성을 제공하려면 이것을 사용하세요. 예를 들어 공통 키와 특정 키를 가질 수 있습니다. 특정 키가 제공되지 않으면 무작위 항목이 삽입되고 그 반대의 경우도 마찬가지입니다.

기본 키에 대한 점수 계산 논리는 1개 일치 = 1점입니다.

보조 키의 경우 상호 작용은 선택한 선택적 논리에 따라 다릅니다:

1. AND ANY: 1개 보조 일치 = 1점.
2. AND ALL: 모두 일치하면 모든 보조 키에 대해 1점.
3. NOT ANY 및 NOT ALL: 변경 없음.

예:

* 항목 1. 키: song, sing, Black Cat. 그룹: songs
* 항목 2. 키: song, sing, Ghosts. 그룹: songs

입력 `sing me a song`은 두 항목을 모두 활성화할 수 있지만(둘 다 2개의 키를 활성화함) `sing me a song about Ghosts`는 항목 2만 활성화합니다(3개의 키를 활성화함).

### 자동화 ID

[STscripts](/For_Contributors/st-script.md)를 Quick Replies 확장 기능과 통합할 수 있습니다. 빠른 응답 명령과 WI 항목 모두 동일한 자동화 ID를 가지고 있으면 일치하는 ID를 가진 항목이 활성화될 때 명령이 자동으로 실행됩니다.

자동화는 트리거된 순서대로 실행되며 [캐릭터 Lore 삽입 전략](#character-lore-insertion-strategy)과 '우선순위' 정렬을 결합하여 지정된 정렬 전략을 준수합니다. 이로 인해 [파란색 원](#strategy) 항목이 먼저 처리되고 다른 항목이 지정된 '순서'로 처리됩니다. 재귀적으로 트리거된 항목은 동일한 순서로 나중에 처리됩니다.

스크립트 명령은 동일한 자동화 ID를 가진 여러 항목이 활성화되면 한 번만 실행됩니다.

### 캐릭터 필터

이 항목을 활성화할 수 있는 캐릭터 이름 목록입니다. 이 목록이 비어 있지 않으면 이름이 목록에 있는 캐릭터에 대해서만 항목이 활성화됩니다. 태그가 선택되면 해당 특정 태그가 있는 캐릭터에 대해서만 항목이 활성화됩니다.

"제외" 모드는 필터를 반전시켜 목록에 추가되거나 선택한 태그가 있는 캐릭터를 제외한 모든 캐릭터에 대해 항목이 활성화됩니다.

### 트리거

이 World Info 항목을 활성화할 수 있는 생성 유형입니다. 아무것도 선택하지 않으면 모든 생성 유형에 대해 항목을 활성화할 수 있습니다. 하나 이상을 선택하면 해당 특정 생성 유형에 대해서만 항목이 활성화됩니다:

* **Normal:** 일반 메시지 생성 요청.
* **Continue:** Continue 버튼을 누를 때.
* **Impersonate:** Impersonate 버튼을 누를 때.
* **Swipe:** 스와이프로 생성이 트리거될 때.
* **Regenerate:** 솔로 채팅에서 Regenerate 버튼을 누를 때.
* **Quiet:** 배경 생성 요청, 일반적으로 [확장 기능](/extensions/index.md) 또는 [STscript](/For_Contributors/st-script.md) 명령에 의해 트리거됩니다.

!!!
"Regenerate" 트리거는 다른 재생성 논리를 사용하는 그룹 채팅에서는 사용할 수 없습니다: 마지막 응답의 모든 메시지가 삭제되고 선택한 [그룹 응답 전략](/Usage/Characters/groupchats.md#reply-order-strategies)에 따라 "일반" 생성 유형을 사용하여 메시지가 대기열에 추가됩니다.
!!!

### 추가 일치 소스

기본적으로 World Info 항목은 현재 대화의 콘텐츠에 대해서만 일치됩니다. 이러한 옵션을 사용하면 채팅에 표시되지 않는 다른 캐릭터 정보 또는 페르소나 정보와도 항목을 일치시킬 수 있습니다. 이는 여러 캐릭터 간에 사용할 광범위한 항목을 원하지만 큰 태그 목록을 관리하거나 새 캐릭터를 만들 때마다 캐릭터 필터 목록을 업데이트하고 싶지 않을 때 유용합니다. 또한 활성화된 페르소나에 따라 항목을 일치시킬 수 있습니다.

* **Character Description**: 캐릭터 설명과 일치시킵니다.
* **Character Personality**: 고급 정의 아래에 있는 캐릭터 성격 요약과 일치시킵니다.
* **Scenario**: 고급 정의 아래에 있는 캐릭터 지정 시나리오와 일치시킵니다.
* **Persona Description**: 현재 선택한 페르소나의 설명과 일치시킵니다.
* **Character's Note**: 고급 정의 아래에서 찾을 수 있는 캐릭터의 노트와 일치시킵니다.
* **Creator's Notes**: 고급 정의 아래에서 찾을 수 있는 캐릭터 제작자의 노트와 일치시킵니다. 제작자의 노트는 일반적으로 프롬프트에 포함되지 않습니다.

## Vector Storage 일치

Vector Storage 확장은 최근 채팅 메시지와 World Info 항목 내용 간의 유사성을 사용하여 키워드 일치에 대한 대안을 제공합니다.

이를 활성화하고 사용하려면 다음 전제 조건을 충족해야 합니다:

1. Vector Storage 확장이 활성화되어 있고 사용 가능한 임베딩 소스 중 하나를 사용하도록 구성되어 있습니다.
2. Vector Storage 확장 설정에서 "Enable for World Info" 확인란이 선택되어 있습니다.
3. 키가 없는 일치가 허용된 World Info 항목이 "Vectorized" (🔗) 상태이거나 Vector Storage 설정에서 "Enabled for all entries" 옵션이 선택되어 있습니다.

확장의 벡터화 모델 선택과 "임베딩"이라는 용어의 이론적 의미는 여기서 다루지 않습니다. 이 주제에 대한 자세한 정보가 필요한 경우 [Data Bank](/Usage/Characters/data-bank.md#vector-storage) 가이드를 확인하세요.

Vector Storage 일치는 이 규칙 집합을 준수합니다:

* Vector Storage와 일치할 수 있는 최대 항목 수는 "Max Entries" 설정으로 조정할 수 있습니다. 이 숫자는 제한만 설정하며 World Info에 대한 활성화 설정에 설정된 토큰 예산에는 영향을 미치지 않습니다. 모든 예산 규칙이 여전히 적용됩니다.
* 이 기능은 키워드 확인만 대체합니다. 항목이 삽입되려면 모든 추가 확인을 충족해야 합니다: 트리거%, 캐릭터 필터, 포함 그룹 등.
* 활성화 설정 또는 항목 재정의의 "Scan Depth" 설정은 사용되지 않습니다. 대신 일치시킬 텍스트를 가져오기 위해 Vector Storage "Query messages" 값이 사용됩니다. 이를 통해 "Scan Depth"가 0으로 설정되어 일반 키워드 일치가 수행되지 않지만 항목이 벡터에 의해 여전히 활성화될 수 있는 구성이 가능합니다.
* "Vectorized" 상태는 추가 마커일 뿐입니다. 항목은 키워드가 설정된 경우 키워드에 의해 활성화될 일반, 활성화, 비상수 레코드처럼 계속 작동합니다. 벡터에 의해서만 활성화되기를 원하면 키워드를 제거하세요.

!!!info Note
검색 품질은 전적으로 임베딩 모델의 출력에 의존하므로 정확히 어떤 항목이 삽입될지 예측하는 것은 불가능합니다. 결정론적이고 예측 가능한 결과를 원한다면 키워드 일치를 사용하세요.
!!!

## 시간 제한 효과

일반적으로 World Info 평가는 상태가 없으며 현재 채팅 컨텍스트에만 의존하여 평가 결과가 동일합니다. 그러나 시간 제한 효과의 도입으로 활성화 지연이 있거나 트리거된 후 활성 상태를 유지하거나 활성화 후 트리거할 수 없는 항목을 만들 수 있습니다.

### 시간 제한 효과 규칙

1. 효과의 시간 프레임은 메시지로 측정됩니다(메시지 쌍/교환이 아님). 0은 효과가 없음을 의미합니다.
2. 효과는 항목이 활성화된 채팅에만 적용됩니다. 분기는 상위 채팅의 상태를 상속합니다.
3. 채팅이 진행되지 않으면 활성 시간 제한 효과가 제거됩니다. 예를 들어 마지막 메시지가 스와이프되거나 삭제된 경우.
4. 현재 시간 제한 효과가 있는 항목을 변경하면 효과가 강제로 제거됩니다.
5. 키워드가 연속적으로 트리거되어도 이미 활성 상태인 경우 효과 지속 시간이 새로 고쳐지지 않습니다.

### 시간 제한 효과 유형

1. Sticky - 항목이 활성화된 후 N개의 메시지 동안 활성 상태를 유지합니다. Sticky 항목은 만료될 때까지 후속 스캔에서 확률 확인을 무시합니다.
2. Cooldown - 항목이 활성화된 후 N개의 메시지 동안 활성화할 수 없습니다. sticky와 함께 사용할 수 있습니다: sticky 기간이 끝나면 항목이 cooldown에 들어갑니다.
3. Delay - 평가 시점에 채팅에 최소 N개의 메시지가 없으면 항목을 활성화할 수 없습니다.
    * Delay = 0 -> 항목을 언제든지 활성화할 수 있습니다.
    * Delay = 1 -> 채팅이 비어 있으면(인사 없음) 항목을 활성화할 수 없습니다.
    * Delay = 2 -> 채팅에 0개 또는 하나의 메시지만 있으면 항목을 활성화할 수 없습니다. 등등.

### 시간 제한 효과 예

항목 구성: sticky = 3, cooldown = 2, delay = 2.

```txt
메시지 0: delay
메시지 1: 항목 활성화됨
메시지 2: sticky
메시지 3: sticky
메시지 4: sticky
메시지 5: cooldown
메시지 6: cooldown
메시지 7: 항목을 다시 활성화할 수 있음
```

## 활성화 설정

World Info 화면 상단의 접을 수 있는 메뉴입니다.

### 스캔 깊이

> 항목 수준에서 재정의할 수 있습니다.

World Info 키에 대해 채팅 기록에서 스캔해야 하는 메시지 수를 정의합니다.

* 0으로 설정하면 재귀된 항목과 작성자 노트만 평가됩니다.
* 1로 설정하면 SillyTavern은 마지막 메시지만 스캔합니다.
* 2 = 마지막 두 메시지 등.

### 이름 포함

채팅 참가자의 이름을 메시지 접두사로 스캔된 텍스트 버퍼에 포함할지 정의합니다. 이를 통해 메시지에서 이름을 직접 언급하지 않고도 이름을 키워드로 사용하는 항목을 활성화할 수 있습니다.

채팅 참가자가 Alice와 Bob이라고 가정할 때 스캔할 텍스트의 예를 아래에서 확인하세요.

활성화됨(기본값):

```txt
Alice: Hello! Good to see you.
Bob: How is the weather today?
```

비활성화됨:

```txt
Hello! Good to see you.
How is the weather today?
```

### Context % / Budget

**한 번에 World Info 항목에서 사용할 수 있는 토큰 수를 정의합니다.**
API의 최대 컨텍스트 설정(Context %)과 관련된 임계값 또는 객관적인 토큰 임계값(Budget)을 정의할 수 있습니다.

예산이 소진되면 키가 프롬프트에 있더라도 더 이상 항목이 활성화되지 않습니다.

상수 항목이 먼저 삽입됩니다. 그런 다음 순서 번호가 큰 항목이 삽입됩니다.

키를 직접 언급하여 삽입된 항목은 다른 항목의 내용에 언급된 항목보다 우선순위가 높습니다.

### Min Activations

**이 설정은 Max Recursion Steps와 상호 배타적입니다.**

Minimum Activations: 0이 아닌 값으로 설정하면 "scan-depth"의 제한을 무시하고 min activations에 지정된 만큼의 항목이 트리거될 때까지 최신 메시지에서 키워드에 대해 모든 채팅 로그를 거꾸로 검색합니다. 이것은 여전히 Max Depth 설정 또는 전체 Budget 상한에 의해 제한됩니다.

*Min Activations에 의해 트리거된 추가 스캔 스윕은 이전 단계의 재귀에 의해 추가된 항목을 확인하지 않습니다. 채팅 메시지와 확장 프롬프트만 이러한 추가 활성화를 트리거할 수 있습니다. 그러나 Min Activations에 의해 활성화된 항목은 평소대로 다른 항목을 트리거할 수 있습니다.*

### Max Depth

Min Activations 설정을 사용할 때 스캔할 최대 깊이입니다.

### 재귀 스캔

재귀 스캔을 사용하면 항목이 다른 항목을 활성화하거나 다른 항목에 의해 활성화될 수 있어 다양한 World Info 항목 간의 복잡한 상호 작용 및 종속성을 가능하게 합니다. 이 기능은 창의적인 시나리오의 동적 특성을 크게 향상시킬 수 있습니다.
재귀 스캔 활성화 여부는 전역 설정 **Recursive Scan**으로 제어할 수 있습니다.
각 항목에 대해 재귀를 제어할 수 있는 세 가지 옵션이 있습니다:

* **Non-recursable**: 이 확인란을 선택하면 항목이 다른 항목에 의해 활성화되지 않습니다. 변경되거나 다른 world info 항목의 영향을 받아서는 안 되는 정적 정보에 유용합니다.

* **Prevent further recursion**: 이 옵션을 선택하면 이 항목이 활성화되면 다른 항목을 트리거하지 않습니다. 의도하지 않은 활성화 체인을 피하는 데 도움이 됩니다.

* **Delay until recursion**: 이 항목은 재귀 확인 중에만 활성화됩니다. 즉, 초기 패스에서는 트리거되지 않지만 재귀가 활성화된 다른 항목에 의해 활성화될 수 있습니다. 이제 해당 지연에 대한 **Recursion Level**이 추가되어 항목이 레벨별로 그룹화됩니다. 처음에는 첫 번째 레벨(가장 작은 숫자)만 일치합니다. 일치하는 항목이 없으면 다음 레벨이 일치 대상이 되며 모든 레벨이 확인될 때까지 프로세스가 반복됩니다. 이를 통해 특히 NOT ANY 또는 NOT ALL 키 일치 조합과 같은 기준과 함께 재귀 중에 더 깊은 정보 레이어가 표시되는 방법과 시기를 더 잘 제어할 수 있습니다.

**항목은 내용 텍스트에서 키워드를 언급하여 다른 항목을 활성화할 수 있습니다.**

예를 들어 World Info에 두 개의 항목이 있는 경우:

```txt
항목 #1
키워드: Bessie
내용: Bessie is a cow and is friends with Rufus.
```

```txt
항목 #2
키워드: Rufus
내용: Rufus is a dog.
```

메시지 텍스트에서 **Bessie만** 언급하면 **둘 다** 컨텍스트로 가져옵니다.

### Max Recursion Steps

**이 설정은 Min Activations와 상호 배타적입니다.**

0으로 설정하면 재귀 중첩은 프롬프트 예산에 의해서만 제한됩니다. 0이 아닌 값으로 설정하면 총 스캔 스윕 수를 원하는 최대 "중첩 레벨"로 제한합니다.

예제 값:

* 1은 첫 번째 단계 이후에 확인이 중지되므로 재귀를 효과적으로 비활성화합니다.
* 2는 재귀 항목을 한 번만 활성화할 수 있습니다.
* 3은 재귀를 두 번 트리거할 수 있습니다...

### 대소문자 구분 키

> 항목 수준에서 재정의할 수 있습니다.

**컨텍스트로 가져오려면 항목 키가 World Info 항목에 정의된 대로 대소문자와 일치해야 합니다.**

키가 일반적인 단어이거나 일반적인 단어의 일부인 경우 유용합니다.

예를 들어 이 설정이 활성화되어 있으면 입력에 따라 'rose'와 'Rose' 키가 다르게 처리됩니다.

### 전체 단어 일치

> 항목 수준에서 재정의할 수 있습니다.

하나의 단어만 포함하는 키가 있는 항목은 전체 단어가 검색 텍스트에 있는 경우에만 일치됩니다. 기본적으로 활성화됩니다.

예를 들어 설정이 활성화되어 있고 항목 키가 "king"인 경우 "long live the king"과 같은 텍스트는 일치하지만 "it's not to my liking"은 일치하지 않습니다.

**중요:** 이 설정은 단어를 구분하기 위해 공백을 사용하지 않는 언어(예: 일본어 또는 중국어)와 함께 사용할 때 해로운 영향을 미칠 수 있습니다. 이러한 언어로 항목을 작성하는 경우 꺼두는 것이 좋습니다.

### 오버플로 경고

활성화된 World Info가 할당된 토큰 예산을 초과하면 경고를 표시합니다.
