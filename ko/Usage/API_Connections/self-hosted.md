# 자체 호스팅 AI 모델

!!!warning
이 가이드는 저자의 개인적인 경험과 지식을 기반으로 하며 절대적인 진실이 아닙니다. 모든 진술은 약간의 회의적으로 받아들여야 합니다. 수정 사항이나 제안 사항이 있으면 Discord에 문의하거나 [SillyTavern 문서 저장소](https://github.com/SillyTavern/SillyTavern-Docs)에 PR을 보내주세요.
!!!

## 소개

이 가이드는 PC에서 실행되는 로컬 AI(이제부터 적절한 용어를 사용하여 LLM이라고 부름)와 함께 SillyTavern을 설정하는 데 도움이 됩니다. 기술 지원 질문으로 사람들을 귀찮게 하기 전에 읽으세요.

### 최고의 대형 언어 모델은 무엇인가요?

"최고"에 대한 표준화된 척도가 없기 때문에 이 질문에 답하는 것은 불가능합니다. 커뮤니티에는 Reddit과 Discord에서 진행 중인 충분한 리소스와 토론이 있어 선호하거나 선택하는 모델에 대한 적어도 어느 정도의 의견을 형성할 수 있습니다. 개인차가 있을 수 있습니다.

### 최고의 구성은 무엇인가요?

최고의 또는 확실한 설정이 있다면 구성이 필요할까요? 최고의 구성은 귀하에게 맞는 것입니다. 시행착오 과정입니다.

## 하드웨어 요구 사항 및 방향

이것은 복잡한 주제이므로 필수 사항만 고수하고 일반화하겠습니다.

* 인터넷에서 다운로드할 수 있는 수천 개의 무료 LLM이 있습니다. Stable Diffusion에 이미지를 생성할 수 있는 수많은 모델이 있는 것과 유사합니다.
* 수정되지 않은 LLM을 실행하려면 많은 VRAM(GPU 메모리)이 있는 괴물 GPU가 필요합니다. 당신이 가질 수 있는 것보다 더 많습니다.
* GPTQ 또는 AWQ와 같은 양자화 기술을 사용하여 모델을 압축하여 VRAM 요구 사항을 줄일 수 있습니다. 이렇게 하면 모델이 다소 덜 유능해지지만 실행하는 데 필요한 VRAM 요구 사항이 크게 줄어듭니다. 갑자기 이를 통해 3080과 같은 게임용 GPU를 가진 사람들이 13B 모델을 실행할 수 있게 되었습니다. 양자화되지 않은 모델만큼 좋지는 않지만 여전히 좋습니다.
* 더 나아집니다: GGUF(이전에는 GGML)라는 모델 형식과 양자화도 있습니다. 이것은 괴물 GPU가 없는 일반 사람들을 위한 선택 형식이 되었습니다. 이를 통해 GPU 없이도 LLM을 사용할 수 있습니다. CPU와 RAM만 사용합니다. 특히 프롬프트 처리 중에는 GPTQ/AWQ를 사용하여 GPU에서 LLM을 실행하는 것보다 훨씬 느립니다(아마도 15배). 그러나 모델의 능력은 똑같이 좋습니다. GGUF 제작자는 게임급 GPU를 가진 사람들이 모델의 일부를 GPU로 오프로드하여 모델의 일부를 GPU 속도로 실행할 수 있도록 하는 구성 옵션을 추가하여 GGUF를 더욱 최적화했습니다(이것은 RAM 요구 사항을 줄이지 않고 생성 속도만 향상시킵니다).
* 다양한 크기의 모델이 있으며 훈련된 매개변수 수를 기반으로 이름이 지정됩니다. 7B, 13B, 30B, 70B 등과 같은 이름을 볼 수 있습니다. 이것들을 모델의 뇌 크기로 생각할 수 있습니다. 13B 모델은 동일한 모델 제품군의 7B보다 더 유능할 것입니다: 동일한 데이터로 훈련되었지만 더 큰 뇌는 지식을 더 잘 유지하고 더 일관되게 생각할 수 있습니다. 더 큰 모델은 더 많은 VRAM/RAM도 필요합니다.
* 여러 정도의 양자화가 있습니다(8비트, 5비트, 4비트 등). 낮을수록 모델이 더 저하되지만 하드웨어 요구 사항은 낮아집니다. 따라서 나쁜 하드웨어에서도 원하는 모델의 4비트 버전을 실행할 수 있을 것입니다. 3비트 및 2비트 양자화도 있지만 이 시점에서는 죽은 말을 때리는 것입니다. k_s, k_m, k_l 등으로 명명된 추가 양자화 하위 유형도 있습니다. k_m은 k_s보다 낫지만 더 많은 리소스가 필요합니다.
* 컨텍스트 크기(모델이 대화의 일부를 삭제하지 않고 대화가 얼마나 길어질 수 있는지)도 VRAM/RAM 요구 사항에 영향을 미칩니다. 다행히도 이것은 구성 가능한 설정이므로 더 작은 컨텍스트를 사용하여 VRAM/RAM 요구 사항을 줄일 수 있습니다. (참고: Llama2 기반 모델의 컨텍스트 크기는 4k입니다. Mistral은 8k로 광고되지만 실제로는 4k입니다.)
* 2023년 어느 시점에 NVIDIA는 GPU 드라이버를 변경하여 GPU가 가진 것보다 더 많은 VRAM이 필요한 경우 작업이 충돌하는 대신 대체로 일반 RAM을 사용하기 시작합니다. 이것은 LLM의 쓰기 속도를 망치지만 모델은 여전히 작동하고 동일한 품질의 출력을 제공합니다. 다행히도 이 동작은 [비활성화할 수 있습니다](https://nvidia.custhelp.com/app/answers/detail/a_id/5490).

위의 모든 것을 고려할 때 하드웨어 요구 사항과 성능은 모델의 제품군, 모델의 유형, 모델의 크기, 양자화 방법 등에 따라 완전히 다릅니다.

#### 모델 크기 계산기
[Nyx's Model Size Calculator](https://huggingface.co/spaces/NyxKrage/LLM-Model-VRAM-Calculator)를 사용하여 필요한 RAM/VRAM의 양을 결정할 수 있습니다.

기억하세요. [디스크 스와핑](https://serverfault.com/a/48487)을 일으키지 않고 메모리에 맞출 수 있는 가장 크고 덜 양자화된 모델을 실행하고 싶습니다.

## LLM 다운로드

시작하려면 LLM을 다운로드해야 합니다. LLM을 찾고 다운로드하는 가장 일반적인 장소는 HuggingFace입니다. 수천 개의 모델을 사용할 수 있습니다. GGUF 모델을 찾는 좋은 방법은 bartowski의 계정 페이지를 확인하는 것입니다: <https://huggingface.co/bartowski>. GGUF를 원하지 않으면 동일한 모델에 대한 다른 형식을 찾을 수 있는 원본 모델 페이지를 링크합니다.

주어진 모델의 페이지에서 전체 파일 묶음을 찾을 수 있습니다.

* 모두 필요하지 않을 수 있습니다! GGUF의 경우 .gguf 모델 파일(일반적으로 4-11GB)만 필요합니다. 여러 개의 큰 파일을 찾으면 일반적으로 동일한 모델의 모든 다른 양자화이며 하나만 선택하면 됩니다.
* .safetensors 파일(GPTQ 또는 AWQ 또는 HF 양자화 또는 양자화되지 않을 수 있음)의 경우 파일 이름에 model-00001-of-00003.safetensors와 같은 숫자 시퀀스가 표시되면 전체 모델을 얻으려면 해당 3개의 .safetensors 파일 + 저장소의 다른 모든 파일(토크나이저, 구성 등)이 모두 필요합니다.
* 2024년 1월 기준으로 Mixtral MOE 8x7B는 로컬 LLM의 최첨단으로 널리 간주됩니다. 실행할 32GB RAM이 있으면 반드시 시도해 보세요. 32GB RAM 미만인 경우 Kunoichi-DPO-v2-7B를 사용하세요. 크기에도 불구하고 즉시 뛰어납니다.

### Kunoichi-DPO-v2-7B 다운로드 연습

이 가이드의 나머지 부분에서는 Kunoichi-DPO-v2-7B 모델을 사용합니다. Mistral 7B를 기반으로 한 훌륭한 모델로 7GB RAM만 필요하며 무게 이상으로 펀치합니다. 참고: Kunoichi는 Alpaca 프롬프트를 사용합니다.

* <https://huggingface.co/brittlewis12/Kunoichi-DPO-v2-7B-GGUF>로 이동합니다
* 'Files and versions'를 클릭합니다. 여러 파일 목록이 표시됩니다. 이들은 모두 동일한 모델이지만 다른 양자화 옵션으로 제공됩니다. 6비트 양자화를 제공하는 'kunoichi-dpo-v2-7b.Q6_K.gguf' 파일을 클릭합니다.
* 'download' 버튼을 클릭합니다. 다운로드가 시작되어야 합니다.

### 모델 유형을 식별하는 방법

TheBloke와 같은 좋은 모델 업로더는 설명적인 이름을 제공합니다. 그렇지 않으면:

* 파일 이름이 .gguf로 끝남: GGUF CPU 모델 (당연히)
* 파일 이름이 .safetensors로 끝남: 양자화되지 않거나 HF 양자화, GPTQ 또는 AWQ일 수 있습니다
* 파일 이름이 pytorch-***.bin: 위와 동일하지만 모델이 로드될 때 임의의 Python 스크립트를 실행할 수 있는 이전 모델 파일 형식이며 안전하지 않은 것으로 간주됩니다. 모델 제작자를 신뢰하거나 절망적인 경우에도 사용할 수 있지만 옵션이 있으면 .safetensors를 선택하세요.
* config.json이 있나요? quant_method가 있는지 확인하세요.
* q4는 4비트 양자화를 의미하고 q5는 5비트 양자화를 의미합니다. 등등
* -16k와 같은 숫자가 보이나요? 컨텍스트 크기가 증가했습니다(즉, 모델이 채팅 시작을 잊기 전에 대화가 얼마나 길어질 수 있는지)! 더 높은 컨텍스트 크기는 더 많은 VRAM이 필요합니다.

## LLM 서버 설치: Oobabooga 또는 KoboldAI

이제 LLM이 PC에 있으므로 SillyTavern과 모델 사이의 중개자 역할을 할 도구를 다운로드해야 합니다: 모델을 로드하고 SillyTavern이 유료 웹 서비스인 OpenAI GPT 또는 Claude와 통신하는 것과 같은 방식으로 SillyTavern이 통신할 수 있는 로컬 HTTP 웹 API로 기능을 노출합니다. 사용해야 하는 도구는 KoboldAI 또는 Oobabooga(또는 기타 호환 도구)여야 합니다.

이 가이드는 두 옵션을 모두 다루며 하나만 필요합니다.

!!!warning
Docker에서 SillyTavern을 호스팅하는 경우 **http://127.0.0.1:\<port\>** 대신 **http://host.docker.internal:\<port\>**를 사용하세요. SillyTavern이 Docker 컨테이너에서 실행되는 서버에서 API 엔드포인트에 연결하기 때문입니다. Docker의 네트워크 스택은 호스트와 분리되어 있으므로 루프백 인터페이스가 공유되지 않습니다.
!!!

### KoboldCpp 다운로드 및 사용 (설치 필요 없음, GGUF 모델)

1. https://koboldai.org/cpp를 방문하면 다운로드할 수 있는 다양한 파일과 함께 최신 버전이 표시됩니다.
작성 시점에 나열된 최신 CUDA 버전은 cu12이며 최신 Nvidia GPU에서 가장 잘 작동합니다. 구형 GPU 또는 다른 브랜드가 있는 경우 일반 koboldcpp.exe를 사용할 수 있습니다. 구형 CPU가 있는 경우 KoboldCpp가 모델을 로드하려고 할 때 충돌할 수 있습니다. 그런 경우 _oldcpu 버전을 사용해 보세요.
2. KoboldCpp는 설치할 필요가 없으며 KoboldCpp를 시작하면 즉시 Model 필드 옆의 Browse 버튼을 사용하여 위에 링크된 것과 같은 GGUF 모델을 선택할 수 있습니다.
3. 기본적으로 KoboldCpp는 SillyTavern에서 이를 더 높게 설정하더라도 최대 4K 컨텍스트에서 실행됩니다. 더 높은 컨텍스트에서 모델을 실행하려면 모델을 시작하기 전에 이 화면에서 컨텍스트 슬라이더를 조정하세요. 컨텍스트 크기가 더 많다는 것은 (비디오) 메모리 요구 사항이 더 높다는 것을 의미합니다. 이를 너무 높게 설정하거나 시스템에 비해 너무 큰 모델을 로드하면 KoboldCpp는 GPU에 맞지 않는 레이어에 대해 자동으로 CPU 사용을 시작하며 이는 훨씬 느립니다.
4. Launch를 클릭하면 모든 것이 잘 진행되면 KoboldAI Lite로 새 웹 페이지가 열리며 모든 것이 올바르게 작동하는지 테스트할 수 있습니다.
5. SillyTavern을 열고 API Connections(상단 바의 2번째 버튼)를 클릭합니다
6. API를 Text Completion으로 설정하고 API Type을 KoboldCpp로 설정합니다.
7. server URL을 <http://127.0.0.1:5001/>로 설정하거나 동일한 시스템에서 실행되지 않는 경우 KoboldCpp가 제공한 링크로 설정합니다(어디서나 액세스할 수 있는 링크를 얻으려면 KoboldCpp의 Remote Tunnel 모드를 활성화할 수 있습니다).
8. Connect를 클릭합니다. 성공적으로 연결되고 kunoichi-dpo-v2-7b.Q6_K.gguf를 모델로 감지해야 합니다.
9. 캐릭터와 채팅하여 작동하는지 테스트합니다.

### KoboldCpp 속도 최적화 팁
1. Flash Attention은 메모리 요구 사항을 줄이는 데 도움이 되며 시스템에 따라 더 빠르거나 느릴 수 있으며 기본값보다 GPU에 더 많은 레이어를 맞출 수 있습니다.
2. KoboldCpp는 문제를 방지하기 위해 레이어를 추측할 때 다른 소프트웨어를 위한 공간을 남겨두므로 열린 프로그램이 적고 GPU에 모델 전체를 맞출 수 없는 경우 몇 개의 추가 레이어를 추가할 수 있습니다.
3. 모델이 컨텍스트 크기에 비해 너무 많은 메모리를 사용하는 경우 KV를 양자화하여 줄일 수 있습니다. 이것은 출력 품질을 낮추지만 GPU에 더 많은 레이어를 넣는 데 도움이 될 수 있습니다. 이렇게 하려면 KoboldCpp의 Tokens 탭으로 이동한 다음 Context Shifting을 비활성화하고 Flash Attention을 활성화합니다. 이렇게 하면 Quantized KV Cache 슬라이더가 잠금 해제됩니다. 낮은 숫자는 메모리 / 모델의 지능이 적다는 것을 의미합니다.
4. 프롬프트를 처리하는 데 오래 걸리는 느린 시스템에서 KoboldCpp를 실행하고 있나요? Context Shifting은 Lorebook, 무작위화 또는 입력을 동적으로 변경하는 기타 기능을 사용하지 않을 때 가장 잘 작동합니다. context shifting을 활성화하면 KoboldCpp가 긴 재처리 시간을 피하는 데 도움이 됩니다.

### Oobabooga 설치

더 정확하고 확실한 설치 절차는 다음과 같습니다:

1. git clone <https://github.com/oobabooga/text-generation-webui> (또는 브라우저에서 저장소를 .zip으로 다운로드한 다음 추출)
2. start_windows.bat 또는 OS에 맞는 것을 실행합니다
3. 묻는 경우 GPU 유형을 선택합니다. GGUF/CPU를 사용하려는 경우에도 GPU가 목록에 있으면 지금 선택하세요. GPU 샤딩이라는 속도 최적화 옵션을 사용할 수 있는 옵션을 제공합니다(처음부터 다시 설치할 필요 없음). 게임급 dGPU(NVIDIA, AMD)가 없으면 None을 선택합니다.
4. 설치가 완료될 때까지 기다립니다
5. kunoichi-dpo-v2-7b.Q6_K.gguf를 text-generation-webui/models에 배치합니다
6. text-generation-webui/CMD_FLAGS.txt를 열고 내부의 모든 것을 삭제하고 다음을 작성합니다: --api
7. Oobabooga를 다시 시작합니다
8. <http://127.0.0.1:5000/docs>를 방문합니다. FastAPI 페이지가 로드되나요? 그렇지 않으면 어딘가에서 실수한 것입니다.

### Oobabooga에서 모델 로드

1. 브라우저에서 <http://127.0.0.1:7860/>을 엽니다
2. Model 탭을 클릭합니다
3. 드롭다운에서 Kunoichi DPO v2 모델을 선택합니다. llama.cpp 로더를 자동으로 선택했어야 합니다.
4. (선택 사항) 이전에 'GPU 오프로드'를 여러 번 언급했습니다: 이 페이지의 n-gpu-layers 설정입니다. 사용하려면 모델을 로드하기 전에 값을 설정하세요. 기본 참조로 30으로 설정하면 13B 이하 모델의 경우 6GB VRAM 미만을 사용합니다. (모델 아키텍처와 크기에 따라 다릅니다)
5. Load를 클릭합니다


### Oobabooga와 통신하도록 SillyTavern 구성

1. API Connections(상단 바의 2번째 버튼)를 클릭합니다
2. API를 Text Completion으로 설정합니다
3. API Type을 Default (Oobabooga)로 설정합니다
4. server URL을 <http://127.0.0.1:5000/>로 설정합니다
5. Connect를 클릭합니다. 성공적으로 연결되고 kunoichi-dpo-v2-7b.Q6_K.gguf를 모델로 감지해야 합니다.
6. 캐릭터와 채팅하여 작동하는지 테스트합니다
