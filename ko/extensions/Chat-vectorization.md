# Chat Vectorization

!!!warning 면책 조항
이 확장 기능의 사용이 더 나은 채팅 경험이나 향상된 메모리를 보장하지 않습니다. 벡터 데이터베이스 활용의 모든 의미를 이해하는 경우에만 사용하세요.
!!!

Chat vectorization은 최근 메시지와 관련성이 있는 것으로 보이는 현재 채팅 기록의 메시지를 검색합니다.
채팅 기록의 시작 또는 끝으로 가장 관련성이 높은 메시지를 일시적으로 이동시킵니다.
이는 모델이 마지막 메시지에 대한 응답을 생성할 때 발생합니다.

채팅 기록의 시작과 끝에 있는 메시지는 모델의 응답에 가장 큰 영향을 미치는 경향이 있습니다.
따라서 관련 메시지를 이러한 위치로 이동시키면 모델이 응답의 관련 정보에 집중하는 데 도움이 될 수 있습니다.

특히 chat vectorization은 요청 컨텍스트에 맞지 않을 정도로 메시지 기록에서 너무 뒤에 있는 관련 메시지를 찾을 수 있습니다. 이러한 메시지를 컨텍스트로 이동시키면 모델에 그렇지 않으면 가지지 못했을 정보를 제공합니다.

Chat vectorization은 일종의 검색 증강 생성(RAG)입니다. 검색 증강 생성은 프롬프트에 추가 관련 정보를 제공하여 모델이 생성하는 응답의 품질을 높입니다.

* 검색: 최근 메시지를 사용하여 관련 과거 메시지를 검색합니다
* 증강: 유용한 방식으로 과거 메시지를 삽입하여 모델의 컨텍스트를 증강합니다
* 생성: 응답을 생성할 때 과거 메시지를 사용하도록 모델에 지시합니다

!!!info 몇 가지 용어:
*벡터*는 텍스트의 주제, 내용, 스타일 또는 기타 특성을 나타낼 수 있는 숫자 집합입니다.

*벡터화*는 텍스트를 나타내는 벡터를 계산하는 것입니다. 이것은 벡터화 모델에 의해 수행됩니다.
텍스트 생성 모델이 텍스트에서 텍스트를 만드는 것처럼 벡터화 모델은 텍스트에서 벡터를 만듭니다.

*벡터 검색*은 키워드 등이 아닌 벡터를 비교하여 관련 결과를 찾습니다. 검색 쿼리에 대한 벡터를 계산하면 텍스트 조각 컬렉션에 대해 저장된 벡터와 비교할 수 있습니다. 이렇게 하면 검색 쿼리의 텍스트와 가장 유사한 컬렉션의 텍스트를 찾습니다. chat vectorization의 경우 "검색 쿼리"는 최근 2개 메시지이고 "컬렉션의 텍스트"는 채팅의 다른 모든 메시지입니다.
!!!

## 설정

!!!warning 프롬프트 캐싱 호환성
동적 프롬프트 소스(World Info, Summarization 등)와 마찬가지로 Chat Vectorization은 LLM 호출 사이에 프롬프트 접두사를 재구성하여 빈번한 캐시 미스를 초래할 수 있습니다. 캐싱과 함께 사용하면 벡터화는 종종 역효과를 낳습니다. 수정된 프롬프트가 캐시를 거의 히트하지 않아 캐싱이 쓸모없게 됩니다. 둘 중 하나를 선택해야 하지만 둘 다 선택할 수는 없습니다.
!!!

Chat vectorization을 활성화하려면 "Extensions" > "Vector Storage" > "Enabled for chat messages"를 선택하세요.

벡터화 소스 및 벡터화 모델을 구성하세요. Chat vectorization은 Data Bank와 동일한 벡터 소스를 사용하므로 이미 설정했을 수 있습니다. Vectorization Source 및 Vectorization Model에 대한 설정은 [Data Bank](/Usage/Characters/data-bank.md)에 문서화되어 있습니다.

Chat vectorization은 Data Bank와 동일한 벡터 스토리지를 사용하지만 설정하거나 구성할 필요가 없습니다.
Vector Storage에 대한 정보도 [Data Bank](/Usage/Characters/data-bank.md)에 있습니다.

Chat vectorization은 Data Bank를 사용하여 채팅 메시지를 저장하지 않습니다. 메시지는 채팅에 저장됩니다.

## 검색을 위한 채팅 메시지 준비(벡터 스토리지)

채팅 메시지를 검색할 수 있도록 각 메시지에 대한 벡터가 계산되고 저장됩니다.

벡터화는 메시지를 보내거나 받을 때마다 백그라운드에서 발생합니다.

각 메시지는 생성 중에 개별적으로 찾고 이동시킬 수 있도록 개별적으로 저장됩니다.

큰 메시지는 모델이 긴 메시지의 가장 관련성이 높은 부분을 제공받을 수 있도록 "청크"로 분할됩니다. 청크 크기는 400자입니다.
"Chunk size (chars)"로 변경할 수 있습니다.

메시지는 단락 나누기, 줄 바꿈 또는 단어 사이의 공백과 같은 청크 경계를 찾아 청크로 나뉩니다. 이것은 가능한 한 모든 청크가 의미가 있도록 하기 위한 것입니다. 채팅 메시지에 `----`와 같은 자연스러운 분할 지점을 표시하는 다른 방법이 있는 경우 "Chunk boundary"에 추가할 수 있습니다. "Chunk boundary" 설정은 Data Bank와 공유됩니다.

### 벡터 스토리지 제어

백그라운드에서 처리될 때까지 기다리지 않고 현재 채팅의 모든 메시지에 대한 벡터를 계산하려면 설정에서 "Vectorize All"을 선택하세요.

현재 채팅에서 벡터화된 메시지 수를 보려면 "View Stats"를 선택하세요. 저장된 벡터의 총 수가 표시됩니다.
또한 벡터화된 특정 채팅 메시지를 녹색 공으로 표시하여 나타냅니다.

현재 채팅의 메시지에 대한 모든 벡터를 제거하려면 "Purge Vectors"를 선택하세요.

!!!
**Chat vectorization 내의** "Vectorize All" 및 "Purge Vectors" 제어는 현재 채팅에 대한 저장된 벡터에만 영향을 미칩니다.
그러나 Data Bank의 파일에 대한 벡터에 영향을 미치는 File vectorization에 동일한 버튼이 있습니다. 제거하려는 벡터를 제거하고 있는지 확인하세요.
!!!

## 이동시킬 관련 메시지 찾기(벡터 검색)

채팅 기록에서 가장 관련성이 높은 메시지를 찾기 위해 최근 메시지가 쿼리 벡터로 변환(벡터화)됩니다. 기본적으로 최근 2개 메시지가 사용됩니다. 이를 변경하려면 "Query messages"의 값을 변경하세요. 이 값은 Data Bank에서 관련 콘텐츠를 찾을 때도 사용됩니다.

과거 메시지가 포함되려면 관련성 점수가 최소 25%여야 합니다. "Score threshold"로 변경할 수 있습니다. 점수 임계값 설정은 Data Bank와 공유됩니다.

채팅 기록에서 가장 관련성이 높은 3개 메시지가 이동됩니다. "Insert#"로 변경할 수 있습니다.

채팅의 최근 이벤트를 방해하지 않으려면 최근 5개 메시지는 이동되지 않습니다. 이를 변경하려면 "Retain#"의 값을 변경하세요.

## 메시지 이동(증강 생성)

메시지는 3개 위치 중 하나로 이동됩니다:

* 채팅 상단, Main Prompt / Story String 뒤(기본값)
* 채팅 상단 및 Main Prompt / Story String *전*
* 채팅 끝, 마지막 2개 메시지 전("In-chat @ Depth 2"). 방금 메시지를 보냈기 때문에 이 위치는 일반적으로 모델의 이전 응답 바로 앞입니다.

"Injection Position" 및 "Depth"로 변경할 수 있습니다.

메시지는 관련성 순서로 포함되며 관련성이 더 높은 메시지는 관련성이 낮은 메시지 뒤에 표시됩니다.

각 메시지를 보낸 사람 또는 캐릭터의 이름이 포함됩니다.

메시지는 "과거 이벤트"로 모델에 표시됩니다. 이것은 메시지가 삽입된 지점과 다른 채팅 기록 지점의 정보를 포함한다는 것을 모델이 이해하는 데 도움이 됩니다. "Injection Template"로 변경할 수 있습니다.

Prompt Itemization 팝업, 터미널 로그 또는 브라우저 콘솔 로그를 사용하여 모델에 대한 최종 프롬프트를 볼 수 있습니다. 브라우저 콘솔 로그는 Chat vectorization의 모든 단계가 수행하는 작업을 이해하는 데 유용합니다.

## 벡터 요약

!!!warning 경고
벡터 요약 기능은 실험적입니다.

**벡터 요약은 채팅의 요약을 만들지 않습니다. 검색된 메시지를 요약으로 바꾸지 않습니다. 채팅 기록을 더 짧게 만들지 않습니다. "[Summarize](/extensions/Summarize.md)보다 나은" 것이 아닙니다.**
!!!

벡터 요약은 채팅 메시지의 벡터 검색을 더 효과적으로 만들기 위한 것입니다. 벡터화 전에 요약 단계를 도입하여 이를 수행합니다. 요약 단계는 메시지의 가장 중요한 부분을 추출하여 결과 벡터가 메시지가 관련된 것을 더 잘 나타내도록 합니다.

벡터 요약은 벡터 검색을 덜 효과적으로 만들 수 있습니다.

채팅 기록의 메시지를 요약하고 각 요약된 메시지에 대한 벡터를 생성하려면 "Summarize chat messages for vector generation"을 선택하세요.

요약된 메시지는 채팅의 원본 메시지를 대체하지 않습니다. 벡터 검색이 요약된 메시지의 벡터와 일치하면 원본 메시지가 채팅 기록에서 검색되고 컨텍스트로 이동됩니다. 요약된 버전의 메시지는 Vector Storage에 보관되며 디버깅에 유용할 수 있습니다.

채팅 기록을 검색하는 데 사용되는 메시지의 내용을 요약하려면(기본적으로 마지막 2개 메시지) "Summarize chat messages when sending"을 선택하세요.

벡터화를 위해 메시지가 요약될 때마다 요약 모델에 별도의 요청이 이루어집니다. "Summarize with"로 사용할 요약 소스를 선택할 수 있습니다. "Main API"를 선택하면 채팅 또는 텍스트 완성을 생성하는 데 사용하는 것과 동일한 모델 및 연결 설정을 사용하여 요약이 생성됩니다.

요청은 원시 메시지 내용과 모델이 요약을 생성하는 방법에 대한 지시로 구성됩니다. "Summary Prompt"로 지시를 변경할 수 있습니다.
